## 무료 호출 조건

- 앱 콘솔의 사용자 제공 캡처에서 카카오맵 유료 API는 **사용 안 함**으로 표시되고 연결된 비즈월렛은 표시되지 않았다. 월간 쿼터는 3,000,000건 중 17건 사용, 2,999,983건 잔여였다. [카카오 유료 API 안내](https://developers.kakao.com/docs/ko/app-setting/paid-api)
- 앞서 공유된 일간 캡처 기준으로 도보 978건, 대중교통 943건, 자동차 단건 9,994건과 다중 목적지 991건이 남아 있었다. 웹 JavaScript 지도 SDK의 개별 일간 사용량은 캡처에서 확인하지 못했다. 첫 묶음은 세 조합으로 제한하고 웹 지도 응답과 쿼터 오류 여부를 함께 확인한다. [카카오 쿼터](https://developers.kakao.com/docs/ko/getting-started/quota) · [카카오모빌리티 무료 제공량](https://developers.kakaomobility.com/price/)
- 최초 시험 서버는 검색당 최대 12회, 최근 60초 12회, UTC 기준 하루 50회로 설정했고 모든 실연동은 같은 공용 장부를 사용했다.

## 외부 호출 없는 로컬 화면 확인

| 환경 | 범위 | 결과 |
| --- | --- | --- |
| Chrome 데스크톱 1366×900 | 출발지 30곳, 전체 90개 조합 | 90건 통과 |
| Edge 모바일 터치 모사 390×844 | O01~O03, 이동수단·시설 유형의 각 조합 1건 | 9건 통과 |
| 기존 서버 테스트와 웹 빌드 | Python 24건, TypeScript 검사, Vite 빌드 | 통과 |

로컬 앱의 데모 API와 지도 화면을 이용했다. 외부 브라우저 요청을 차단했다. 화면에서 좌표·유형·이동수단을 입력해 API 요청이 시험표와 일치하는지, 추천 카드와 거리·시간, 대중교통 구간, 선택 경로선이 표시되는지 확인했다. 터치 시험은 목록과 지도 전환, 상세 복귀 초점과 가로 넘침도 확인했다.

별도 재현용 응답으로 GPS 권한 거부, 주소 조회 실패 후 좌표 입력, 시설 없음, 경로 없음, 검색 오류와 재시도, 호출 한도 안내를 구분해 확인했다. 로컬 HTTP에서 `.env`, `ApiKey.txt`와 시설 DB 요청이 403으로 차단됐고 프런트 빌드에 서버용 REST 키가 포함되지 않았다.

## 실제 웹 인수시험 기록

첫 묶음은 O01 시청앞·덕수궁의 도보 편의점, 대중교통 지하철역, 자동차 공중화장실이다. 실연동 결과는 실행 시각, 브라우저, 추천·평가 수, 검색 중단 사유, 경로선, 외부 호출 수로 기록한다. 사용량 장부에는 API별 시도 수가 남고 재시도 횟수는 별도로 식별되지 않는다.

당일 장부에는 첫 도보 실행을 포함해 총 **42회**가 기록됐다. 세 조합 모두 카카오 쿼터 오류 없이 호출 한도에서 평가를 마친 후보를 표시했다. 자동차는 처음 선택된 시설의 상세 좌표가 추천의 도착점과 일치하는지 확인했다.

## 남은 기기·환경 검증

Safari, 실제 iOS·Android 기기와 화면 읽기 프로그램은 별도 시험 대상이다. 휴대폰에서 접속할 수 있는 HTTPS 시험 주소와 등록된 카카오 SDK 도메인을 준비한 뒤, 위치 권한 허용·거부와 수동 입력, 추천 선택, 지도·목록 전환 및 상세 정보를 확인한다. 기기 모사 결과는 실제 기기 인수 판정과 분리한다. [재개 6단계 기기 확인 범위](검증_FindNearby_재개6모바일접근성.md)
