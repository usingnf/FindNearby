# 재개 6단계 모바일 사용성과 접근성 검증

검증일 2026-11-08. 후속 개발 계획의 기존 7단계에 해당한다. [작업 계획](계획_FindNearby_기존검토및후속개발.md)

## 화면 동작

- 데스크톱은 추천 목록과 지도를 함께 표시한다. 폭 760px 이하에서는 목록과 지도를 전환한다. 카드와 지도 핀은 같은 시설을 선택하며, 지도와 경로 상세 사이를 오가도 선택이 유지된다.
- 카드에서 거리와 예상 시간을 비교한다. 상세는 선택한 경로의 출처를 표시하며, 대중교통은 제공된 환승 횟수, 요금, 이동 구간과 정류장을 표시한다. 상세 조회에 실패하면 추천에 사용한 거리와 시간을 유지하고 재시도 버튼을 제공한다.
- 주소·시설 검색 및 경로 상세의 진행 상태를 알린다. 검색 실패, 일부 실패, 시설 없음, 경로 없음과 호출 제한을 구분한다. 위치 권한 거부나 주소 검색 실패 시 좌표를 직접 입력할 수 있다. 지도 SDK가 실패해도 검색 서버에 연결되어 있으면 실제 추천과 텍스트 경로 상세를 제공한다.
- 출발지 건너뛰기 링크, 시설·이동수단 선택, 지도 핀과 확대·축소 버튼을 키보드로 조작할 수 있다. 검색 버튼을 누르면 결과 제목에, 지도와 상세 사이를 이동하면 해당 제목에 초점을 둔다.

## 브라우저 확인

| 환경 | 확인 결과 |
| --- | --- |
| Windows Chrome · 1366×900 | Tab과 Enter·Space로 주소 선택, 시설·이동수단 지정, 추천, 경로 선택, 확대·축소와 핀 선택을 완료했다. 실제 카카오 지도에서 클릭으로 출발지가 갱신되는지 확인했다. |
| Windows Edge · 390×844 모바일 터치 모사 | 좌표 입력부터 실제 카카오 지하철역 대중교통 추천 3개 표시까지 확인했다. 지도·목록 전환, 확대·축소, 핀 터치, 카드 선택과 경로 상세 초점, 가로 넘침을 확인했다. |
| Windows Edge · 320×760 모바일 터치 모사 | GPS 권한 거부와 지도 SDK 로딩 실패를 재현했다. 주소 오류와 빈 결과, 좌표 입력 후 실제 검색 모드 유지, 경로 없음과 호출 제한을 확인했다. |

Chrome의 주소·추천·상세 응답에는 재현용 데이터를 사용했다. 전체 검색 실패 후 재시도, 부분 실패 시 추천 유지, 상세 실패 후 재조회, 버스·지하철·도보와 환승·요금 표시, 시설 없음 상태를 확인했다. Edge의 지도와 대중교통 추천은 실제 API 응답으로 확인했다. 예외 상황은 브라우저에서 응답과 권한을 제어해 재현했다.

개발용 데모에서도 배경 타일 연결이 끊긴 상태로 지도 핀을 터치하고 같은 가상 시설이 목록에서 선택되는지 확인했다.

기본·보조 글자, 검색 버튼, 선택 상태, 오류 안내와 실제·데모 배지의 글자 대비는 5.82:1 이상이다. 흰 배경에서 초점 테두리는 6.52:1이다. 모바일의 주요 버튼과 입력 높이는 44 CSS px 이상이다. [WCAG 글자 대비 기준](https://www.w3.org/WAI/WCAG21/Understanding/contrast-minimum)

백엔드 자동 테스트 24건, TypeScript 검사와 웹 빌드가 통과했다. Safari, 실제 모바일 기기, 화면 읽기 프로그램은 별도 검증이 필요하다.

개방시간·접근성 필터는 시설별 개방시간과 접근성 정보가 더 확보된 뒤 검토한다. 현재 화면에는 자료에 기재된 개방시간과 확인된 출입구의 출처를 표시한다. [시설 데이터 검증 기록](검증_FindNearby_재개5시설데이터.md)
