## 3. 주요 검증 사례

1. 도보 순위는 시간이 더 긴 경우에도 **보행거리**가 짧은 시설을 상위로 선정.
2. 자동차 순위는 거리가 더 길어도 **주행시간**이 짧은 시설을 상위로 선정.
3. 대중교통 예상시간 동률 시 환승 횟수와 거리순으로 결정.
4. 후보가 1~2곳 또는 경로 없음이 일부 포함된 경우 **유효한 개수만 반환**.
5. 자동차 다중 목적지 응답의 `key`는 숫자 인덱스로 지정하고 실제 시설 ID는 서버에서만 매핑.
6. 자동차 요약 순위 3개가 반환되면 **1위만 상세 좌표를 요청**, 2~3위는 개별 버튼으로 조회.
7. 상세 자동차 경로 조회가 실패해도 **정상적인 요약 순위는 유지**.
8. 반복 동일 경로 추천 시 **3분 캐시**를 사용하여 추가 업스트림 요청을 방지.
9. 잘못된 후보 좌표, 중복 ID, 11개 이상 과다 후보, 지원하지 않는 이동수단을 차단.
10. 업스트림 인증 오류 시 HTTP 오류를 반환하되 **인증키 원문을 포함하지 않음**.
11. UI에서 가상 추천과 실제 추천을 구분하고, 잘못된 서버 응답·응답 순위를 거부.
12. 지도에서 추천한 1~3위와 선택 시설에 대한 경로를 표시하도록 소스 연동.

## 5. 실 API 검증 전 주의사항

- 실제 API 활용 가능 권한·비용, 무료 제공량 및 지리적 서비스 범위는 앱 설정과 제공자 정책에 종속됩니다.
- 하나의 버튼 클릭으로 도보/대중교통 신규 API가 최대 10번 호출될 수 있고, 자동차는 다중 목적지 조회 1회 + 상세 1회가 기본입니다.
- 프로세스 내 일일 50회 호출 한도는 강제 청구 한도가 아닙니다. 재시작 시 초기화되며, 여러 인스턴스에서 합산되지 않습니다.
- 3분 캐시는 운영 사업자의 저장·재이용 정책과 충돌할 수 있으므로 출시 전 확인이 필요합니다.
- 추천의 정확성은 비교한 후보 10개 내에서만 성립하며, 검색 누락/반경/우회/교통 상황을 고려하면 진정한 전국 최단 3개를 보장하지 않습니다.
- 공중화장실 실제 개방·위치 정확도 및 역 출입구·자동차 주차장 도착점은 6단계 이상에서 보완해야 합니다.
