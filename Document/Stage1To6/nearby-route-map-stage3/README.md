# NearPath — 3단계: 주변 시설 검색 및 지도 마커 표시

대한민국 지도 기반 주변 시설 탐색 서비스의 **3단계 개발 프로젝트**입니다. 2단계의 출발지 지정 기능을 유지하면서 **편의점·지하철역·공중화장실 검색, 자동 반경 확대, 시설 마커 및 후보 목록**을 추가했습니다.

> **중요:** 현재 결과는 **직선거리 기준의 시설 후보**입니다. 도보·대중교통·자동차의 실제 경로, 시간, 이동거리 계산은 **4~5단계**에서 연결합니다. API 키가 없는 데모 모드의 시설명·위치는 모두 가상입니다.

## 기능

| 기능 | API 키 없이(개발용) | JavaScript 키 연결 시 |
|---|---|---|
| 지도 표시, 확대·축소 및 지도 클릭 | Leaflet / OpenStreetMap | Kakao Maps JavaScript SDK |
| 출발지 GPS·지도 클릭·좌표 입력 | 가능 | 가능 |
| 주소·장소명으로 출발지 찾기 | 사전 정의된 예시 8개만 | 실제 카카오 주소·장소 검색 |
| 편의점 `CS2` | 출발지 주변 가상 시설 | 카카오 카테고리 검색 |
| 지하철역 `SW8` | 출발지 주변 가상 시설 | 카카오 카테고리 검색 |
| 공중화장실 | 출발지 주변 가상 시설 | '공중화장실' 키워드 검색(임시) |
| 지도상 시설별 마커 및 목록 | 가능 | 가능 |
| 시설별 직선거리, 검색 반경 표시 | 가능 | 가능 |
| 실제 경로·예상 소요시간 및 최적 3개 추천 | **4~5단계 예정** | **4~5단계 예정** |

공중화장실은 카카오 로컬 API에 별도 카테고리 코드가 없기 때문에 키워드 기반 임시 검색을 사용합니다. 이용 가능 시간, 실제 출입구, 영업 상태를 확인하지 않습니다. **공공데이터 통합은 6단계**에서 검토합니다.

## Windows 사용 방법

1. Node.js **22.16 이상** 설치: https://nodejs.org/
2. ZIP을 압축 해제하고 `START_WINDOWS.bat` 파일을 더블클릭합니다.
3. 브라우저에서 `http://localhost:5173`으로 접속합니다.
4. 왼쪽의 `서울시청`, `판교역` 등 예시 장소를 선택하거나 지도를 클릭해서 **출발지**를 지정합니다.
5. **주변 시설 검색**에서 `편의점 / 지하철역 / 공중화장실` 중 하나를 선택합니다.
6. 초기 검색 반경을 지정한 뒤 **주변 시설 검색** 버튼을 누릅니다.
7. 목록에서 시설을 클릭하거나 지도에 표시된 숫자 마커를 클릭해 선택합니다.
8. 출발지 또는 시설 유형을 변경하면 이전에 검색한 사용자는 결과가 자동 갱신됩니다.

개발용 모드에서는 **가상 시설**이라고 명시하며, 현장에 해당 시설이 실제로 있다는 뜻이 아닙니다. 지도 배경의 OSM 공개 타일을 받으려면 인터넷 연결이 필요합니다.

## macOS / Linux 또는 수동 실행

```bash
npm install
npm run dev
```

`http://localhost:5173`을 엽니다. Windows에서도 같은 명령을 사용할 수 있습니다.

## 이후 카카오 JavaScript 키 연결

1. 카카오디벨로퍼스 https://developers.kakao.com/ 에서 앱을 등록하고 카카오맵 사용 설정을 켭니다.
2. **JavaScript 키**의 **JavaScript SDK 도메인**에 `http://localhost:5173`을 등록합니다.
3. `.env.example`을 복사하여 `.env`를 만듭니다.
4. 아래와 같이 **JavaScript 플랫폼 키만** 입력합니다.

   ```dotenv
   VITE_KAKAO_JS_KEY=발급받은_JavaScript_키
   ```

5. 개발 서버를 재시작합니다. `카카오맵 연결됨`이 표시되면 실제 카카오맵 지도와 시설 검색을 사용합니다.

**REST API 키는 `.env`의 `VITE_` 변수에 절대 넣으면 안 됩니다.** 해당 값은 브라우저에 포함되어 외부에 노출됩니다. 4단계의 경로 API는 **서버 측에서 REST 키를 보관**하도록 구현해야 합니다.

검색에는 지도 SDK의 `services.Places.categorySearch`(`CS2`, `SW8`)와 `keywordSearch`('공중화장실')를 사용합니다. 서비스 조회에는 설정된 출발지 좌표가 카카오 검색 서비스로 전송됩니다. 애플리케이션 자체는 위치 검색 결과를 서버·파일·로컬스토리지에 자동 저장하지 않습니다.

## 검색 및 후보 선정 정책

- 지원하는 초기 반경: **500m / 1km / 3km / 5km / 10km / 20km**
- 출발지 중심으로 검색, 거리순 정렬, 1페이지 최대 15건
- 후보가 **10개 미만이면 다음 반경**으로 자동 확장 (최대 20km)
- 한 반경에서 결과가 충분하지 않고 다음 페이지가 존재할 때 **최대 2페이지** 요청
- 모든 반경과 페이지를 합쳐 최종 후보 **최대 15개**
- 중복 ID, 동일 이름·인접 좌표, 유효하지 않은 좌표, 반경 밖 데이터를 제외
- **직선거리만 계산**하므로 하천, 철도, 진입로, 우회로와 환승·교통상황은 아직 반영하지 않음
- 최대 검색 호출은 반경 6단계 × 2페이지 = 12회 / 검색. 사용자 요청 때마다 API 사용량이 발생할 수 있습니다.
- 주소 검색과 달리 시설 검색은 카카오 로컬 검색 데이터가 제공하는 업체·장소에 한정됩니다. 검색 결과가 전국의 모든 시설을 망라한다고 보장하지 않습니다.
- 예시 모드는 API 호출 0회, 출발지 주변에 가상 점을 생성하는 방식입니다.

검색 API가 오류를 반환하면 빈 목록으로 가장하지 않고 오류 안내를 표시합니다. 출발지·시설·반경 변경으로 새로운 검색이 시작된 경우 이전 검색 응답이 늦게 도착하더라도 화면에 덮어쓰지 않도록 했습니다. 이는 이미 시작한 API 요청의 **과금을 취소한다는 뜻은 아닙니다**.

## 개인정보 및 이용 정책

- GPS는 브라우저 권한 허용 후에만 사용합니다(HTTPS 또는 `localhost`).
- 주소·시설 검색을 사용하면 좌표 등 관련 검색 정보가 외부 카카오 SDK에 전달될 수 있습니다.
- 공용 OSM 타일 서비스는 **임시 개발용**이며, 상용·대규모 서비스에서는 타일 제공 계약 및 이용 정책을 확인하거나 카카오맵으로 대체해야 합니다.
- 카카오 지도 SDK 사용 조건, 무료 적용 앱, 무료 사용량·과금 설정을 출시 전에 확인해야 합니다.

## 이어서 진행할 개발 (4단계)

`FacilityCandidate`에 `id`, `type`, `name`, `coords`가 있으므로 다음 단계 경로 계산 요청의 목적지로 그대로 사용할 수 있습니다. 4단계에서는 서버에 REST API 키를 보관하고 보행/대중교통/자동차 경로 데이터 표준화 모듈을 추가합니다. 그 후 5단계에서 실제 이동거리/시간으로 후보를 재정렬합니다.
