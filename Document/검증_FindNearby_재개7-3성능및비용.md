# 재개 7-3 성능·호출량 측정

2026-11-09 기준. 선택한 실연동 15개와 외부 호출 없는 부하·한도 시험을 마쳤다. 화면 표시를 계측한 실연동 12개를 집계했다. 전국 규모의 성능·운영 비용 판정에는 추가 표본이 필요하다. [7-2 인수시험 기록](검증_FindNearby_재개7-2화면인수시험.md) · [성능 요구사항](REQUIREMENTS_DEFINITION_SRS_v1.0.md#8-비기능-요구사항)

## 측정 방법

검색 버튼 클릭부터 추천 카드 또는 검색 완료 상태가 렌더링되는 프레임까지 브라우저 시계로 잰다. 추천 HTTP 응답과 별도 경로 상세 요청의 시간도 따로 기록한다. P95는 시간을 정렬해 전체 건수의 95%에 해당하는 순번을 올림해 구한다. 검색별 한도, 공급자 오류, 시간 초과는 정상 완료 표본과 분리한다. 정상적인 시설·경로 없음은 완료 상태의 하나로 기록한다. [브라우저 시험 실행법](../Dev/tests/안내_FindNearby_테스트.md#재개-7-2-브라우저-인수시험)

## 실제 카카오 응답

| 시험 | 화면 표시 | 추천 HTTP | 결과 | REST 시도 |
| --- | ---: | ---: | --- | ---: |
| O02-W 홍대입구역 도보 지하철역 | 612ms | 361ms | 추천 3개, 4곳 평가, 실제 경로선, 검색별 한도 | 6회 (시설 2, 도보 4) |

O02-W는 남은 호출 여유에 맞춰 검색 상한 6회로 실행했다. 나머지 11개는 기본 검색 상한 12회로 실행했다. [추가 실연동의 조합별 시간](검증_FindNearby_재개7-2화면인수시험.md#2026-11-09-추가-실연동)

| 계측한 실연동 표본 | 표본 수 | 화면 표시 범위 | 화면 P95 |
| --- | ---: | ---: | ---: |
| 최대 반경까지 검색 완료 | 2 | 505~3162ms | 3162ms |
| 검색별 또는 분당 호출 한도 도달 | 10 | 612~2833ms | 2833ms |

정상 종료 표본 2건은 함평터미널 도보 시설 없음과 대중교통 추천이다. 두 결과 모두 10초 이내였다. 표본 2건의 P95는 느린 한 건과 같으므로 전체 서비스의 P95 10초 목표 판정은 보류한다.

## 외부 호출 없는 브라우저 부하

Chrome 데스크톱에서 순차와 동시 조건으로 각각 90개 조합을 데모로 실행했다. 지도 SDK와 외부 타일 요청을 차단했다. 아래 시간은 개발 환경의 화면 처리 기준이며, 실연동 지도·네트워크·경로 응답 시간을 포함하는 인수 지표와 구분한다.

| 실행 조건 | 표본 | 화면 P50 | 화면 P95 | 추천 HTTP P95 |
| --- | ---: | ---: | ---: | ---: |
| 단일 브라우저 순차 실행 | 90 | 252ms | 259ms | 5ms |
| 브라우저 3개 동시 실행 | 90 | 254ms | 260ms | 6ms |

## 서버 동시 호출과 장애 재현

실제 추천 코드와 SQLite 한도에 가짜 공급자를 연결했다. 공급자 응답마다 30ms 지연을 넣었다. 시나리오별 임시 장부로 격리했으며, 다음 수치는 모의 공급자 시도 수다.

| 시나리오 | 시도 수 | 확인 결과 |
| --- | ---: | --- |
| 사용자 1명 | 9 | 시설 조회 6회, 경로 3회. 353.1ms에 추천 3개 |
| 사용자 4명 동시 | 12 | 시설 조회 4회, 경로 8회. 125.9~155.5ms에 1~3개 반환. 네 요청 모두 분당 한도 안내 |
| 일시적 공급자 502 | 10 | 한 번 재시도해 추천 3개. 재시도 1회가 장부에 추가됨 |
| 정상 경로 없음 | 9 | 평가한 3곳 모두 경로 없음. 결과 0개와 공급자 실패 0건 |
| 공급자 429 | 2 | 첫 경로 호출에서 제한 확인. 추가 호출 없이 제한 사유 반환 |

동시 실행 시간이 더 짧았던 경우 각 요청은 더 적은 후보를 평가했다. 응답시간과 추천 충실도를 함께 기록한다.

별도 브라우저 재현으로 빠른 중복 클릭과 중간 이동수단 요청이 합쳐지는지, 늦은 응답이 최신 결과를 덮어쓰지 않는지, 연결 중단 후 다시 검색할 수 있는지 확인했다. 자동 테스트 24건, 브라우저 시험 스크립트 문법 검사, TypeScript 검사와 웹 빌드도 통과했다.

## 호출량과 비용 범위

- 사용자 제공 콘솔 기준 카카오맵 유료 사용은 꺼져 있었다. 추가 11개 시험의 외부 REST 호출 124회는 카테고리 27회, 키워드 16회, 도보 19회, 대중교통 37회, 자동차 단건 10회, 다중 목적지 15회다. 카카오 쿼터 오류는 없었다. 웹 지도 SDK 사용량과 실제 청구액은 콘솔에서 별도 확인한다. [카카오 쿼터](https://developers.kakao.com/docs/ko/getting-started/quota) · [카카오모빌리티 무료 제공량](https://developers.kakaomobility.com/price/)
- 공용 장부는 48회에서 172회로 늘었다. 사용자 승인으로 시험 프로세스에만 적용한 일일 상한 500회 이내였고, 분당·검색별 12회 한도는 유지했다. 공용 응답 캐시가 없으므로 적중률은 해당 없음이다.
