## 1. 프로젝트 개요

### 1.1 개발 목적

대한민국 내 임의의 출발 위치에서 사용자가 선택한 시설 유형에 해당하는 가까운 시설 2~3개를 탐색하고, 각 시설까지의 이동 경로를 제공하는 웹 기반 서비스를 개발한다.

단순 직선거리가 아닌 실제 도로망과 대중교통 경로를 이용하여 이동수단별 최적 목적지를 추천한다.

### 1.2 주요 목표

1. 대한민국 전역의 지도 및 위치 검색 지원
2. 출발 위치에서 주변 시설 자동 검색
3. 편의점, 지하철역, 공중화장실 검색
4. 도보, 대중교통, 자동차 경로 지원
5. 이동수단에 따른 가까운 시설 최대 3개 추천
6. 추천 시설의 경로, 이동거리, 예상 소요시간 표시
7. PC 및 모바일 웹 환경에서 사용 가능
8. 향후 시설 종류 및 이동수단 확장이 가능한 구조

## 4. 이동수단별 경로 요구사항

| 항목 | 도보 | 대중교통 | 자동차 |
|---|---|---|---|
| 기본 추천 기준 | 최단거리 | 최단시간 | 최단시간 |
| 경로 계산 | 보행 가능 경로 | 버스·지하철·도보 조합 | 차량 주행 가능 도로 |
| 필수 거리 정보 | 총 도보거리 | 총 이동거리 | 총 주행거리 |
| 필수 시간 정보 | 예상 보행시간 | 예상 총 소요시간 | 예상 주행시간 |
| 추가 정보 | 경로 안내 | 노선·정류장·환승·요금 | 통행료 등 제공 가능한 정보 |
| 경로 표시 | 보행 경로선 | 이동수단별 구간선 | 차량 경로선 |
| 순위 결정 | 거리 오름차순 | 시간 오름차순 | 시간 오름차순 |

### 4.1 도보

- 실제 보행 가능한 경로를 탐색한다.
- 보행 최단거리를 기본 기준으로 사용한다.
- 보행로, 횡단 가능 위치, 우회 경로 등을 경로 데이터가 제공하는 범위에서 반영한다.
- 출발지와 목적지가 지나치게 가깝거나 일치하는 상황을 처리한다.

### 4.2 대중교통

- 버스, 지하철 및 도보 연결 구간을 포함한다.
- 전체 이동시간을 기준으로 시설을 추천한다.
- 환승 횟수와 이용 노선을 표시한다.
- API에서 제공하는 요금을 표시한다.
- 대중교통 경로가 존재하지 않으면 결과에서 제외하거나 별도로 경로 없음 상태를 표시한다.
- 짧은 거리에서는 대중교통 이용보다 도보가 적합할 수 있음을 안내한다.
- 조회 결과를 실시간 버스 도착 보장 정보로 표시해서는 안 된다.

### 4.3 자동차

- 자동차가 통행할 수 있는 도로망을 사용한다.
- 예상 주행시간을 기본 추천 기준으로 사용한다.
- 교통상황 반영 여부를 제공 API의 특성에 따라 명시한다.
- 주차장 진입점 또는 차량 접근 가능한 도착 위치를 사용하도록 설계한다.
- 실제 주차 가능 여부를 보장하지 않는다.
- 경로 소요시간과 시설 진입까지 필요한 시간이 다를 수 있음을 안내한다.

**공통 규칙:** 이동수단을 변경할 때 기존 추천 3개를 그대로 유지하지 않는다. 새로운 이동수단으로 후보 경로를 다시 평가하여 순위를 결정한다.

## 5. 시설 검색 및 추천 알고리즘

### 5.1 검색 범위

초기 검색 반경:

- 도보: 500m
- 대중교통: 2km
- 자동차: 2km

반경은 후보 부족 여부에 따라 500m, 1km, 3km, 5km, 10km, 20km 등으로 확장한다. 중간 단계는 이동수단에 따라 생략할 수 있다.

20km를 초과하는 전국 단위 검색은 제공 API의 검색 제약을 검증한 뒤 별도 처리한다.

### 5.2 후보 선정

1. 출발 위치와 시설 유형을 입력받는다.
2. 검색 API에서 주변 시설 목록을 조회한다.
3. 중복·좌표 오류 등을 제거한다.
4. 직선거리 순으로 후보를 정리한다.
5. 초기에는 가까운 후보 10~15개를 우선 평가한다.
6. 각 후보에 대해 선택한 이동수단의 경로 계산을 요청한다.
7. 경로가 없는 시설은 유효한 추천 대상에서 제외한다.
8. 이동수단별 추천 기준으로 정렬한다.
9. 상위 3개를 반환한다.
10. 최종 결과가 부족하면 후보 또는 검색 범위를 확대한다.

### 5.3 검색 정확도

검색된 최초 10~15개 후보만 평가하여 절대적인 최단거리 시설이라고 단정해서는 안 된다.

결과 정확도를 높이기 위해 추가 후보 탐색, 페이지 처리, 직선거리 하한을 이용한 탐색 종료 판단을 적용한다.

결과 화면에서는 기본적으로 **'검색된 시설 중 추천 경로 상위 3개'**로 표현하며, 전국 모든 시설을 완전 탐색한 결과인 것처럼 표현하지 않는다.

### 5.4 순위가 같은 경우

동일한 평가 점수가 발생하면 다음 기준을 순서대로 사용한다.

- 도보: 거리 → 소요시간 → 시설 식별자
- 대중교통: 소요시간 → 환승 횟수 → 도보거리 → 시설 식별자
- 자동차: 소요시간 → 주행거리 → 시설 식별자

## 6. 사용자 화면 요구사항

### 6.1 지도 화면

- 출발지 마커
- 목적 시설 마커
- 시설 유형 선택 UI
- 이동수단 선택 UI
- 현재 위치 선택 버튼
- 주소 검색
- 검색 실행 버튼
- 검색 결과 목록
- 선택한 경로 시각화

### 6.2 시설 추천 결과

각 추천 결과는 다음 정보를 가진다.

| 공통 필드 | 설명 |
|---|---|
| 순위 | 1~3위 |
| 시설 이름 | 시설명 |
| 시설 유형 | 편의점·역·화장실 |
| 주소 | 도로명 주소 등 |
| 거리 | 선택한 경로의 이동거리 |
| 예상 소요시간 | 선택한 경로의 예상 시간 |
| 상태 | 경로 계산 성공 여부 |
| 상세 경로 | 이동수단별 경로 상세 정보 |

### 6.3 지도 경로 표시

추천된 최대 3개 시설은 모두 지도 마커로 표시한다.

기본적으로 1위 경로를 강조하고, 나머지 시설을 선택하면 선택된 경로로 강조 표시를 전환한다.

경로는 단순한 출발지·도착지 직선이 아니라 경로 API가 제공한 실제 이동 경로 좌표로 표현한다.

## 9. 데이터 요구사항

### 9.1 위치 정보

- 표준 좌표계: WGS84
- 저장 형식: 위도(latitude), 경도(longitude)
- 외부 API의 좌표 순서가 경도·위도일 경우 변환 처리
- 부정확하거나 존재하지 않는 좌표 검증

### 9.2 시설 데이터

**필수 필드**

- 시설 식별자
- 시설명
- 시설 유형
- 위치 좌표
- 데이터 출처

**선택 필드**

- 주소
- 영업 또는 개방시간
- 전화번호
- 출입구·주차장 좌표
- 데이터 갱신 일자

### 9.3 경로 데이터

- 출발 위치
- 목적 시설 식별자
- 이동수단
- 이동거리(미터)
- 예상 소요시간(초)
- 경로 좌표 목록
- 이동 구간 정보
- 경로 계산 시점
- 경로 계산 상태
- 요금·환승 등 이동수단별 추가 정보

## 10. 권장 기술 스택

| 영역 | 권장 기술 |
|---|---|
| 웹 프론트엔드 | React + TypeScript |
| UI 빌드 | Vite |
| 지도 렌더링 | Kakao Maps JavaScript SDK |
| 백엔드 | Python FastAPI |
| 시설 검색 | Kakao Local API |
| 도보 경로 | Kakao Maps Walking Routing API |
| 대중교통 경로 | Kakao Maps Public Transit Routing API |
| 자동차 경로 | Kakao Mobility Directions API |
| 공공시설 데이터 | 공공데이터포털 등 검증된 출처 |
| 초기 저장소 | 서버 설정 및 필요 최소한의 데이터 |
| 향후 공간 DB | PostgreSQL + PostGIS |
| API 통신 | HTTPS / REST / JSON |

지도 제공자와 경로 계산 제공자를 교체할 수 있도록 각 API 연동 코드는 별도 인터페이스로 분리한다.

## 11. 최초 개발 범위에서 제외할 기능

다음 기능은 추후 확장 대상으로 정의한다.

- 사용자 로그인 및 계정 관리
- 즐겨찾기 및 개인별 검색 기록
- 위치를 지속 추적하는 실시간 내비게이션
- 실시간 경로 이탈 감지와 자동 재탐색
- 출발 예정시각 지정 및 예약 길찾기
- 실시간 버스·열차 도착 정보 보장
- 실시간 주차 가능 대수 조회
- 장애인·휠체어 접근성 전용 경로 보장
- 자전거 및 기타 이동수단
- 전국 자체 도로·보행 그래프 구축
- 오프라인 지도와 오프라인 경로 탐색

## 12. MVP 인수 테스트

최초 버전은 다음 조건을 충족해야 한다.

| ID | 인수 조건 |
|---|---|
| AT-01 | 주소 검색과 지도 클릭으로 출발지를 설정할 수 있다. |
| AT-02 | 위치 권한이 없어도 서비스를 사용할 수 있다. |
| AT-03 | 3가지 시설 유형이 각각 검색된다. |
| AT-04 | 3가지 이동수단의 경로 조회가 각각 동작한다. |
| AT-05 | 선택한 이동수단별로 시설 추천 순위가 재계산된다. |
| AT-06 | 유효한 결과가 3개 이상이면 최대 3개를 표시한다. |
| AT-07 | 추천 시설 각각의 거리와 예상 시간이 표시된다. |
| AT-08 | 실제 경로 좌표를 이용한 지도 경로선이 표시된다. |
| AT-09 | 대중교통 경로에는 제공된 환승·노선 정보가 표시된다. |
| AT-10 | 시설이 부족하거나 경로가 없는 경우 오류 없이 처리한다. |
| AT-11 | 지도 및 검색 UI가 PC와 모바일에서 정상 작동한다. |
| AT-12 | API 키 보호 및 호출량 제한이 작동한다. |

서울·수도권, 지방 대도시, 농어촌, 강·철도 등 이동 장애물이 존재하는 지역을 포함한 최소 30개 출발지에서 이동수단별 테스트를 실시한다.

## 13. 1단계 기술 검증 항목

요구사항 정의 이후 다음 항목을 반드시 실제 API 호출로 확인한다.

1. 카카오 개발자 앱 및 인증키 생성
2. 지도 JavaScript SDK 정상 출력
3. 편의점·지하철역 카테고리 검색
4. 공중화장실 데이터 확보 및 좌표 정합성 확인
5. 도보 경로 API 요청 및 경로 좌표 수신
6. 대중교통 경로 API 요청 및 구간·환승 정보 수신
7. 자동차 길찾기 API 요청 및 주행 경로 수신
8. 이동수단별 도착점 보정 가능 여부 확인
9. API 상업적 이용, 데이터 저장, 경로 지도 표시 조건 확인
10. API 무료·유료 쿼터 및 예상 운영비 검증

기술 검증에서 특정 API의 이용 권한·요금·기능이 요구사항을 충족하지 못하면 다른 제공자로 대체하고, 기능 요구사항 자체는 유지한다.
